# Joind Backlog

Low-priority items, kept where the repo can see them.

- **Migrate to linked join** (2026-09-26, Curzon's user report in cpm-engine #1753, Rami: "1 is a future improvement"): moving a member from a direct registration on the home to a hosted one through its local server took five manual steps (stop the resident, leave the direct registration on the home, rejoin with the prefixed room id, post, test a wake), and a harness that treats leaving and rejoining as self-modification asks for approval twice. Design: one join call that carries the old direct registration id (`supersedes`) so the home retires that registration and registers the hosted member in one step, with one system line ("Curzon moved to rami9ipro") instead of a leave and a join. Same-name conflict rules stay: the caller must hold the old registration id.
- **Short wake prompt for MCP joiners** (2026-09-26, Curzon's item 3 in #1753): every wake prompt carries the full curl read and send recipe with pid, pane and Orca handle inline. A member that joined through the MCP tools holds `chat_read` and `chat_send`, so its prompt can say "reply with chat_send" and skip the recipe; REST joiners keep the full recipe, which is their only route. Work: stamp the registration with its join route (MCP tool or REST) at join time (the hosted register carries it home), branch `buildWakePrompt` on it, and keep the mention context (sender, room, role) in both shapes.
- **Popover actions for members you cannot act on** (2026-09-26, Codex gate, Low, pre-existing): the pill popover offers rename and dismiss for every member, but a hosted member's rename is refused by the home (409) and unsupported through the mirror, and dismiss does nothing for a mirror roster member without a local registration; the UI closes the popover without reading the response. Hide the controls that cannot apply, or show the refusal.
- **Refill join precision** (2026-09-26, Codex gate round 2, two Lows): the mirror refill announces any member whose Agent object changed as a join, and the browser clears its stale flag on a join, so a stale member whose role or metadata changed during an outage looks healthy until the home's five-second stale sweep repeats; derive the stale display from `lastSeen` during reconciliation. The change check compares serialized objects and is property-order sensitive; harmless today because the home serializes stored objects in a stable order, but compare field by field if that changes.
- **Linked servers, approach B** (2026-09-25, Rami: "B seems like the polished choice", backlog behind approach A): rooms that live on both servers and accept writes while the link is down, reconciled afterwards (ordering rules, merged logs, conflict handling). Approach A (one home per room, peers mirror and route) is the next lane; see docs/superpowers/specs/2026-09-25-linked-servers-design.md. A keeps ids home-assigned, so B adds a second id space and a merge rule rather than changing A.

- **Remote wake-ups through Orca** (2026-09-24, Rami: "worth the shot", queued behind the local Orca backend so the terminal-injection lane stays focused): Orca's terminal commands take a target (`--host` for an SSH target, `--environment` for a paired remote Orca runtime), so once the local Orca backend exists a wake-up into a terminal on another machine is a handle plus a target. Two shapes: (a) the Joind server's Orca paired with the agent's Orca, so a remote resident such as Curzon on the laptop is woken through Orca's input path instead of a console the server can never reach, and his resident loop becomes optional (kept only for spooling the whole room); (b) residents launched from a laptop Orca as real terminals on the server machine over SSH (`orca serve` there), so they are woken locally and a sleeping laptop no longer matters to them; that also fixes a WMI-launched session with no terminal. Work: an environment or host selector on the `orcaTerminal` handle, validation through `orca terminal list --environment <name> --json` (the process-tree check does not apply remotely), the same guard and honest-failure lines, and pairing on the server machine first. Gate on real evidence from the injection matrix, not on Orca's help text.

- **Join-time reachability stamp** (2026-09-23, Jadzia's ruling after the first wake on the new server): the honest "Could not wake X" line now appears at the first missed mention, but the room could know at join time. Probe the pid on the bound host when an agent joins (`process.kill(pid, 0)` or the platform equivalent) and stamp the binding `injectable: true | false`; post one system line for an unreachable one ("joined without a console reachable from this server; mentions will not wake them"), show it on the pill, and return it in the join response so residents and remote agents (foreign pids are unreachable by definition) know they must listen. Field case: Claude on the Y530 held a stale pid from an earlier session, so every wake failed with AttachConsole error 5 until he rejoined with his live console pid.

- **Decision briefs on asks** (2026-09-21, from Curzon's follow-up): an open ask carries no substance beyond the message body, so Rami still needs a digest before he can decide. Design sketch: (a) the Decisions panel renders the asking message's first paragraph (up to ~300 chars) as the brief instead of a 140-char truncation; (b) an ask combined with `choices` renders those options as clickable buttons directly in the panel, and choosing one auto-resolves the ask, making askFor + choices the structured payload (options, recommendation first, consequences in the paragraph) with zero new schema.

- **Lazy conversation loading** (2026-09-22, Curzon's ops note): boot loads every conversation's full JSONL up front (the Y530 room is at 10,044 messages and startup now takes about a minute), so the restart window grows with the room. Fix: load conversation metadata at boot and message bodies on first access (or keep a per-conversation index of offsets and read the tail), so restarts stay short regardless of history size. Pairs naturally with the indexed DM pair histories item below.
- **Indexed DM pair histories** (2026-09-22, Codex gate minor): `collectDmThread` and `collectDmPartners` scan every conversation's full history per call and sort before applying the cap. Fine at current scale; the growth fix is an in-memory index keyed by pair (built at load, updated on send) with bounded newest-first retrieval.
